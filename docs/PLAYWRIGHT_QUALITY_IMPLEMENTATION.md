# McpGo Playwright: качество чтения и скорость (19.11.2026)

Реализовано **в исходниках**, не развёрнуто в установленной пользовательской версии. За основу взяты принципы из `PLAYWRIGHT_REFACTOR_IMPLEMENTATION.md`; ранее незакоммиченные изменения не удалялись.

## Изменения

- Зависимость `@playwright/mcp` закреплена в `package.json`/lockfile на **0.0.86**, транзитивные Playwright и playwright-core — `1.66.0-alpha-2026-11-18`. Патч bounded tab metadata по-прежнему применяется к новому bundle через `npm ci` и fail-closed при несовместимом исходнике. Нативная группа/владение вкладками из 0.0.86 не подменена monkey-patch'ем.
- `mcpgo_inspect_page` предоставляет `auto`/`find`/`snapshot`/`verify`/`visual`. `auto` предпочитает `browser_find`, если передан текст или regex, иначе depth-limited DOM. `snapshot` поддерживает `target`/`depth`/`boxes`; `verify` использует `browser_wait_for` с явным ожидаемым текстом и ограниченным таймаутом; `visual` объединяет доступное дерево с bounding boxes и WebP viewport screenshot. Автоматический скриншот возможен только при `visualFallback: true` и слабом сигнале дерева; иначе DOM остаётся базовым режимом.
- Новая read-only команда использует **тот же** `workspace_id`, локальный TabLease/ownership guard и сериализованную очередь, что и обычный `browser_snapshot`. Она не совершает кликов, не создаёт вкладок и не повторяет неопределённые операции. `browser_close` (закрытие всего браузера) и `browser_run_code_unsafe` запрещены в публичном каталоге/прокси.
- Для Browser MCP settle timeout по умолчанию **200 мс** (`MCPGO_BROWSER_SETTLE_MS`). Отдельный AutoSend остаётся на **500 мс** (`MCPGO_AUTOSEND_SETTLE_MS`), поскольку сам автоматически отправляет сообщения; обе настройки есть в macOS/Windows launcher и валидируются (0–2000 целых миллисекунд).
- Для диагностики `/healthz` и `mcpgo_browser_status` пассивно хранят максимум 20 записей об ошибках: timestamp, HTTP status и нормализованный код. URL, содержимое DOM, запросы, скриншоты, авторизационные данные и capability `workspace_id` в историю не попадают. Тяжёлые trace/скриншоты пользовательских страниц автоматически не записываются.
- Обновлены упаковочные списки macOS и Windows на `page-inspection.mjs`; изменены supply chain notices. В GitHub PR уже есть *информационный* короткий Chrome smoke из предыдущего этапа.

## Сравнение settle timeout

Реальный изолированный Google Chrome, Playwright MCP 0.0.86, по 18 последовательных кликов на одинаковой локальной тестовой странице. Каждый клик завершался отдельной проверкой нового текста в DOM. Цифры — медиана / p95 энд-ту-энд вызова, миллисекунды:

| settle | click median | click p95 | результат |
|---|---:|---:|---|
| 500 мс | 563,1 | 888,5 | PASS |
| 200 мс | 258,1 | 301,3 | PASS |
| 100 мс | 173,1 | 225,8 | PASS |
| 0 мс | 44,3 | 114,7 | PASS |

Принято 200 мс, а не 0: UI с асинхронными запросами требует проверки состояния после действия; сокращённая задержка сама по себе не доказывает завершение операции на сайте. Сохраняем `verify`/`browser_wait_for`. Замеры сделаны в узком тестовом сценарии и не являются гарантированными для реальных сайтов.

## Качество контекста

В режиме `MCPGO_SMOKE_INSPECT=1` QA-сайт содержит 160 нерелевантных ссылок, кнопку, отложенное обновление DOM и canvas.

- Полный accessibility snapshot: **21 262 символа**.
- Точечный `browser_find`: **413 символов**, сокращение примерно **98,1%**.
- Snapshot одного участка: **424 символа**, сокращение примерно **98,0%**.
- Отложенный на 280 мс переход в `Saved` подтверждается `verify` без повторного клика.
- Визуальный режим реально вернул типы `text`, `text`, `image`, `text` в одном ответе.

Это размер ответа *в символах*, не фактическая тарификация токенов и не гарантия сокращения общей продолжительности сценария. Экономия характерна для страниц с большим нерелевантным содержимым.

## Изоляция и границы приёмки

- Доказанный локальный PASS на изолированном Chrome с одним клиентом и всеми новыми видами чтения.
- Тесты парсера, workspace, запрета обхода `browser_close` и защитной очереди выполняются в `node --test playwright/tests/*.test.mjs`.
- Многоклиентный прогон с тремя клиентами **прошёл при повторе** (find/snapshot/verify/visual, свои вкладки, 0 `tools/list`), но первая попытка упёрлась в **40-секундный таймаут холодного открытия вкладки** и была безопасно заблокирована (`BROWSER_ACTION_OUTCOME_UNKNOWN`).
- С тяжёлым DOM (160 ссылок) три клиента отработали корректно, однако наблюдались **плохие задержки**: медиана клика ~3,9 с, p95 ~10,7 с. Без тяжёлого DOM короткий тест трёх клиентов дал медиану ~856 мс. Нельзя утверждать, что 0.0.86 уже быстрее при высокой нагрузке; требуется A/B на новой версии расширения и реальном Chrome перед релизом.
- В Node-наборах Dashboard+Playwright+Windows **152 PASS, 2 SKIP, 0 FAIL**. AutoSend **122/122 PASS**. Python **83/83 + 65/65 + 16/16 PASS**; Terminal **42/42 PASS** на повторной изолированной проверке (первый параллельный прогон дал один таймаут тестового heartbeat под нагрузкой). Автоматическое обновление установленной версии не выполнялось.
- Не меняли автоматически привязку вкладок на новую модель 0.0.86: новая модель требует ручного контроля группы расширением и не даёт автоматически доказательства безопасности пересоздания сессии; пока остаётся McpGo workspace/lease guard.

Реальные профили Chrome, авторизации и рабочие вкладки не затрагивались; использовались временные Chrome-профили и loopback-тестовые страницы. Без коммита, push, сборки дистрибутивов и деплоя.

## Фактическое развёртывание в macOS Dev (19.11.2026)

После первичных проверок изменения **развёрнуты на локальный McpGo Dev**, без коммита, push, продакшн-релиза и изменения `/Applications/McpGo.app`:

- Dev app: `release/dev/McpGo Dev.app`, переподписан для локального тестирования (`codesign --verify --deep --strict`: PASS). В его `RuntimeSeed` установлен Playwright MCP **0.0.86**.
- Запущенные Browser MCP и Proxy перечитали новый исходный runtime и 0.0.86 на портах **8931/8940**. Выделенный браузер AutoSend перезапущен на **8932**, его API на **8972**; default settle **200 мс / 500 мс** проверен по аргументам процессов.
- Протокол через действующий прокси: `2026-07-28`; `tools/list` включает `mcpgo_inspect_page`, `browser_find`, `browser_wait_for`, не раскрывает `browser_close` и `browser_run_code_unsafe`. `mcpgo_workspace`, `mcpgo_browser_status` и реальный read-only `browser_tabs:list` через установленное Chrome Extension завершились успешно. `/healthz`: `browser=connected`, очередь `quarantined=false`, `waiting=0`.
- AutoSend API здоров и не занят, **но** `extensionConnected=false`, пока выделенная группа не выбрала чат. Реальные запланированные отправки, клики по пользовательским вкладкам и обработка сообщений не проверялись.
- Откат: `release/dev/playwright-rollback-20261119/` (старый Dev.app, 47 runtime-файлов, зависимости **0.0.85**), плюс `.mcpgo-085-live-before-dev-20261119/` внутри writable `Runtime/playwright`. Токены, настройки и пользовательские данные не заменялись.

**Важная граница dev:** текущая архитектура McpGo Dev.app использует **общий** writable `~/Library/Application Support/McpGo/Runtime`. На диске `/Applications/McpGo.app` ничего не менялось, однако уже подключённые к общим Browser/AutoSend LaunchAgents клиенты теперь тоже работают с обновлённым runtime. Это не физически изолированный второй MCP-сервер. Перед отдельным публичным релизом необходимо провести QA с установленной версией расширения и устойчивостью под нагрузкой.
