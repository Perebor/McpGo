# ADR-001: AutoSend использует только официальный Playwright MCP Extension

Статус: **утверждено**, 2026-11-16.

## Почему переписываем

Старый AutoSend использовал общую браузерную MCP-сессию всех агентов, текущее положение вкладки и её номер в `browser_tabs`. При редиректе ChatGPT из `/g/g-p-ID/c/UUID` в `/g/g-p-ID-slug/c/UUID` он не узнавал разговор, заново открывал вкладку и снова терял идентичность. Если несколько вкладок имеют одинаковый URL, у публичного Playwright MCP нет стабильного Chrome `tabId`: индекс может измениться. Попытки восстановить tabId по URL и особые ветки в proxy не могут обеспечить надёжность.

## Принятое решение

**Единственный способ взаимодействия с браузером: официальный Playwright MCP + Playwright Chrome/Edge Extension (`--extension`).** CDP endpoint, самописное Chrome Native Messaging расширение и переключение между транспортами не поддерживаются.

**AutoSend имеет отдельный постоянный Playwright MCP backend (127.0.0.1:8932) и отдельную группу вкладок `MCPGO AutoSend`** внутри того же Chrome и профиля, что и обычный MCPGo Browser. Это два клиента официального расширения, но **один браузерный транспорт**. Переключаться между вкладками других агентов AutoSend не должен. Не использовать `--no-tab-group`. Backend/группа живёт независимо от расписаний; API AutoSend на 127.0.0.1:8972 хранит состояние и очередь.

AutoSend **никогда не вызывает `browser_tabs(new)`, `browser_navigate` или `browser_tabs(close)`**. Пользователь один раз даёт расширению доступ к нужному уже открытому разговору (или переносит его в группу AutoSend). Если в видимой группе 0 совпадений — ждать, если >1 — `AMBIGUOUS_CHAT_TABS`, **не выбирать произвольно и не создавать новых вкладок**.

Адрес преобразуется в ключ `project:<project-id>:<conversation-uuid>` либо `direct:<conversation-uuid>`. Произвольный читаемый суффикс проекта игнорируется, но идентификаторы и тип чата должны совпадать. Любой `Send` запрещён, пока повторные наблюдения не подтвердили этот ключ, точную вкладку, свободный редактор, отсутствие чужого черновика и надёжное отсутствие генерации. Состояния `READY`/`BUSY`/`UNKNOWN` не объединять.

* **Read-only проверка:** отдельный API, никаких отправок, создания или перезагрузок вкладок. Нет постоянных DOM-мониторов, которые сами вызывают browser tool без необходимости.
* **Доставка:** single-flight; durable slot-id, pre-click receipt на диске, один атомарный guarded click внутри страницы. До подтверждённого клика можно пропустить текущий слот; после неясного исхода **никаких повторных Send**; только read-only reconciliation и ручная сверка.
* **Работа агента:** признаки Stop/streaming и серверный статус — положительные признаки занятости; внутренний ChatGPT `stream_status` является неофициальным и может исчезнуть. При UNKNOWN — не отправлять. Не утверждать, что публичный интерфейс даёт доказательство серверного idle.
* **Безопасность:** разрешённое действие проверяет совпадение ключа разговора уже внутри вкладки непосредственно перед Send, а не доверяет индексу/заголовку/DOM текста всей страницы. Отправка не должна происходить в группе другого клиента.
* **Пользовательские данные:** сохранить зашифрованные расписания, историю, слоты и receipts. Не стирать их при миграции. При перезапуске неопределённой отправки сохранить UNKNOWN без повтора.

## Явные компромиссы

- Официальный Playwright MCP возвращает **индексы**, не `chrome.tabs.id` ([документация](https://playwright.dev/mcp/tools/tabs)). Внутри выделенной группы требуем не более одной вкладки для каждого разговора. Даже официальное расширение не может доказать серверное завершение ChatGPT при отсутствии достоверных сигналов. Предпочитаем пропуск ошибочной попытке отправки в чужой/занятый чат.
- Расширение поддерживает отдельные клиентские группы ([документация](https://github.com/microsoft/playwright/blob/main/packages/extension/README.md)); это реальная граница владения, вместо самодельной привязки по URL.
- При первом подключении новой выделенной группы может потребоваться один раз выбрать вкладку в расширении. Это ожидаемая настройка, не автоматическое открытие дубликата.

## Отклонённые подходы

- **CDP**: отдельная от пользовательского Chrome диагностика и разрешения; возвращаться к двум транспортам не будем.
- **Собственное расширение с `chrome.tabs.id`**: позволяет сильную идентичность вкладки, но потребует поддерживать свой браузерный движок и дублировать Playwright MCP. Для единого транспорта не выбираем.
- **Общий backend с другими агентами + восстановление по URL**: одинаковые URL неотличимы, переключение других агентов ломает проверку.
- **Автоматически создавать новую вкладку при каждом пропуске**: формирует дубликаты и ухудшает идентичность. Запрещено.

## Windows и проверка упаковки

Windows получает Playwright Extension token через отдельное поле настроек
McpGo: ciphertext хранится в пользовательских настройках `safeStorage`
(Windows DPAPI), отсутствующий токен переводит browser/autoSendBrowser
в `unconfigured`. Служба `autosendBrowser` явно включена в стартовые
сервисы. В Mac Dev bundle переносится новый LaunchAgent
`com.mcphub.autosend.browser` и удаляются два устаревших исходных модуля
AutoSend с резервной копией при локальном обновлении. При этом файлы
`tasks.json`, `message-key` и `control-token` не затрагиваются.
