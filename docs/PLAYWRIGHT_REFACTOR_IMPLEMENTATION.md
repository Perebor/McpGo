## 1. Реальный Chrome и измерения

- `playwright/qa/live-agent-smoke.mjs` получает `mcpgo_workspace` и сохраняет `workspace_id` **до** открытия первой вкладки.
- `playwright/qa/isolated-chrome-smoke.mjs` стартует собственные Playwright MCP, headless **Google Chrome** с временным профилем, защищённый прокси и локальную тестовую страницу на динамических loopback-портах. Существующий пользовательский Chrome и профиль не используются.
- Один или три клиента: `server/discover → workspace → new → select → snapshot → click → проверить счётчик → close`; восстановление отдельного клиента по прежнему `workspace_id`.
- Хранятся только числовые метрики и краткие диагностические ошибки, не страницы/секреты; JSON-отчёт записывается в системную временную папку. В `/healthz` пассивно публикуются числовые `performance`-счётчики без запросов к Chrome.
- Для GitHub PR добавлен **информационный** короткий тест изолированного Chrome; ошибки этого дополнительного шага пока не блокируют CI до подтверждения доступности браузера на runner. Обязательные Node-тесты остаются блокирующими.

Запуск:

```bash
MCPGO_LIVE_BROWSER_SMOKE=1 MCPGO_SMOKE_CLIENTS=1 MCPGO_SMOKE_REPS=100 node playwright/qa/isolated-chrome-smoke.mjs
MCPGO_LIVE_BROWSER_SMOKE=1 MCPGO_SMOKE_CLIENTS=3 MCPGO_SMOKE_REPS=100 node playwright/qa/isolated-chrome-smoke.mjs
```

## 2. Единый ответ JSON/SSE

`playwright/mcp-response.mjs` объединяет чтение JSON-RPC и событий SSE, включая `data:`/`data: `, LF/CRLF, несколько data-строк, heartbeat, уведомления и UTF‑8, разрезанный между чанками. Результат/ошибка распознаются по точному JSON-RPC ID. Неполный результат не считается успешным. Прокси декорирует рабочее пространство и `resultType` за один проход по сообщениям; клиент AutoSend на **отдельном** backend использует тот же модуль и завершает ожидание по результату, даже если поток SSE остаётся открытым.

## 3. Достоверный статус и неопределённые действия

`playwright/browser-session-manager.mjs` различает транспортный сбой, выход браузера/расширения, истечение сессии, ошибку инструмента, подтверждённый ответ инструмента и неизвестный исход. HTTP 200 сам по себе не означает успешное действие на сайте. Результат `503` больше не оставляет статус `connected` с нулём ошибок. Ошибка элемента не запускает отключение Chrome.

После обрыва во время изменяющей операции прокси **не повторяет** её автоматически, помечает receipt `unknown` и переводит общую очередь в защищённое состояние `quarantined` до контролируемого перезапуска. После обрыва **читающего** запроса очередь также блокируется, поскольку он может ещё работать с общей активной вкладкой; подтверждено отдельным интеграционным тестом. Прежде чем разблокировать работу, надо проверить последствия на сайте, а не повторять клик/отправку. Read-only `/healthz` показывает текущее состояние без соединения с Chrome.

## 4. Горячий путь и привязки вкладок

При корректной долгоживущей сессии перед каждым `browser_snapshot` больше **нет** `tools/list`: тест на 100 последовательных снимков проверяет счётчик; при одновременном истечении сессии и восстановлении 3 безопасных запросов выполняется одна инициализация. Потенциально изменяющие команды при истечении или неясном ответе не повторяются.

Проверки `browser_tabs:list` остаются для безопасного выбора, запрета действий по неоднозначному URL и проверки активной вкладки после ручного переключения. Автоматическая оптимизация двух проверок для `mcpgo_tab_action` **не включена**: установленный backend не обеспечивает гарантированной атомарной адресации по opaque `tab_id`. Скорость не важнее изоляции.

## 5. Справедливая очередь

`playwright/browser-queue.mjs` даёт не более трёх последовательных приоритетных операций, пока ожидает обычная; берёт возраст самой старой записи по timestamp, поддерживает общий бюджет 60 секунд поверх подготовки/очереди/проверок/исполнения; отмена до dispatch не выполняется позднее. Клик и смена общей активной вкладки не распараллеливаются. Обрыв после отправки требует безопасного восстановления (см. раздел 3).

**Важное уточнение архитектуры:** действующий AutoSend работает через собственный Playwright Extension MCP на `127.0.0.1:8932`, отдельно от общего proxy `8940`. Поэтому реального вытеснения пользовательских запросов AutoSend *в этой общей очереди* сейчас нет. Ограничитель приоритетов защищает очередь общего прокси от приоритетных клиентов, которые работают именно через него; не заявляется ускорение фактического AutoSend. Проверки справедливости выполнены на детерминированном планировщике, отдельная конкуренция двух независимых backend не моделировалась.
