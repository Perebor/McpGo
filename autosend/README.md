# McpGo AutoSend v2

**Утверждённая архитектура:** [ADR-001](../docs/adr/001-autosend-extension-only.md).

Браузерный транспорт — **только официальное Playwright MCP Chrome/Edge Extension**. AutoSend имеет собственный, постоянно работающий MCP backend на `127.0.0.1:8932` и отдельную группу вкладок `MCPGO AutoSend`. Основной браузерный агент пользуется другим backend (`8931`, внешний safe proxy `8940`). Они не разделяют активную вкладку или группу.

## Первая настройка

1. Откройте нужный разговор в обычном Chrome/Edge, в том же профиле, где установлено официальное Playwright Extension.
2. Через Playwright Extension один раз предоставьте клиенту **MCPGO AutoSend** доступ к этой вкладке. Если вкладка находится в группе другого MCP-клиента, переместите её в выделенную группу AutoSend штатными средствами Chrome/расширения. Не копируйте разговор в десяток одинаковых вкладок.
3. В McpGo нажмите **«Проверить без отправки»**. Эта операция не вводит текст, не нажимает Send и **никогда не открывает новую вкладку**.
4. Когда проверка подтвердит доступность и готовность чата, включите расписание.

Если вкладка не выбрана, сервис вернёт `CHAT_TAB_MISSING`. Если в группе больше одной вкладки этого разговора, вернёт `AMBIGUOUS_CHAT_TABS` и запретит отправку. Ничего автоматически не создаётся, не закрывается и не перегружается.

## Исполнение

- Планировщик: `server.mjs` (порт 8972); данные: `core.mjs`, `schedule.mjs`, `reconciliation.mjs`.
- Подключение: `browser-client.mjs`, **одна** постоянная MCP-сессия официального Extension backend. Пассивный статус порта без вызовов browser tools: `browser-health.mjs`.
- Выбор вкладки, DOM и доставка: `delivery.mjs`, `chat-state.mjs`, `guarded-send.mjs`. Ключ разговора: `playwright/chatgpt-url.mjs` (project ID + chat UUID или отдельный UUID).
- Проверка активности: `stream-monitor.mjs`, признаки DOM и повторные снимки. Внутренний ChatGPT stream_status **не является стабильным публичным API**; неопределённость запрещает Send.
- Один цикл: найти **ровно одну** ранее выбранную вкладку → прочитать состояние → дважды подтвердить готовность → ввести сообщение с submit=false → финальный guard → записать receipt → **один** Send → наблюдать реальную пользовательскую реплику.
- Неопределённость после границы клика: `verifying` → `verified` или `unknown`. Никаких повторов потенциально выполненного Send, даже после перезапуска.
- Интервальные расписания не запускаются раньше наступления следующего слота. Умное продолжение (`after_response`) проверяется отдельно, только read-only.
- `GET /api/status` и `POST /api/tasks` доступны только локальному авторизованному native UI.

## Данные и безопасность

Файл `~/Library/Application Support/McpGo/AutoSend/tasks.json` сохраняет старые задачи, slot ledger и историю. Тексты хранятся в AES-256-GCM, ключ рядом с файлом с правами владельца. Поддерживается **миграция формата хранилища**, но нет прежнего браузерного транспорта. Старые поля watchdog удаляются при следующем запуске; неопределённая отправка при рестарте остаётся неопределённой.

AutoSend не выполняет `browser_tabs(new)`, `browser_tabs(close)`, `browser_navigate` и не использует CDP. Он не запускает отдельный браузер, не скрывает неудачную проверку и не утверждает, что публичный интерфейс ChatGPT даёт доказательство завершения вычислений на сервере.

## Тесты

```sh
node --test autosend/tests/*.test.mjs
node --test playwright/tests/*.test.mjs
```

Интеграционное тестирование **без отправки** через кнопку «Проверить без отправки» безопасно. Реальную однократную отправку проверяют только в выделенном тестовом разговоре по явному запросу.

Для ручной проверки применяются `preview-check.mjs` (до трёх read-only наблюдений): временный HTTP/сетевой сбой `stream_status` повторяется без Send; статус готовности отображается только после **двух** последовательных согласованных `COMPLETE` снимков. Черновик, индикатор работы или чужая вкладка блокируют проверку без повторов.
